## Defects

### A1. Stale confirmation line in the workbench (fixed)

- Steps: Assign tab → transfer ICR to Desk 2 → open ICR → Transfer to Desk 3 → back → Home → Old / pending.
- Expected: no confirmation line, or one that is still true.
- Actual: "ICR261102107012 transferred to Support Desk 2." stayed on screen.
- Fix: `mobile/src/screens/admin/WorkbenchScreen.tsx`. The line is cleared when the tab regains focus and when a home row switches the queue. Test added: `__tests__/admin-journey.test.tsx` "drops the confirmation line when the admin comes back to the workbench from another tab".

### A2. Try again after an error doesn't restore the queue counts (fixed)

- Steps: Assign tab → go offline (adb reverse removed) → pull to refresh → error state → back online → Try again.
- Expected: list and chip counts both return.
- Actual: list returned, chips showed "Unassigned", "Assigned", "Old · pending" with no counts until the next refresh. Screenshot `screens/ADMIN-2-retry-counts.png`.
- Fix: `mobile/src/screens/admin/WorkbenchScreen.tsx`. Try again now reloads the list, the counts and the desk chips. Re-checked on the device.

### A3. Action bar crowded when admin has both Transfer and the desk actions (coordinator)

- Steps: admin → open any assigned open case (e.g. ICR261102107012).
- Expected: three actions readable on one line each, or laid out on two rows.
- Actual: Transfer, Ask dealer and Update case each get a third of the width; "Update case" wraps to two lines. Screenshot `screens/ADMIN-5.png`.
- File: `mobile/src/features/internal/InternalActions.tsx` lines 13–16 and the `bar` style (line 22), with `mobile/src/features/desk/DeskActions.tsx` lines 18–19 (`style={L.flex1}` on both buttons).
- Proposal: when both `canAssign` and `canUpdate` are true, render two rows in `InternalActions`: the admin action full width on top, then the desk row (`<View style={{ gap: spacing.sm }}><View style={s.row}><AdminActions/></View><View style={s.row}><DeskActions/></View></View>`). I tried a compact ghost Transfer button inside `AdminActions` alone; "Update case" still wrapped because the desk buttons are `flex: 1`, so I reverted it.

### A4. Unassigned case shows "Handled by PQMP Support" to admin (coordinator)

- Steps: admin → Assign tab → open ITD261101106998 (unassigned).
- Expected: "Not assigned yet" (internal view), consistent with the workbench "Not assigned".
- Actual: "Handled by PQMP Support".
- Cause: `mobile/src/mock/server.ts` line 156 sends `D.SUPPORT_NAME` as `handledBy` for internal users when there's no desk; `mobile/src/screens/case-detail/CaseDetailScreen.tsx` line 53 only falls back to "Not assigned yet" for a blank name.
- Proposal: in `CaseDetailScreen.tsx:53` use `internalView ? (detail.assignedDesk ? displayText(detail.assignedDesk.name) : 'Not assigned yet') : customerFacingOwner(detail.handledBy.name)`, and/or make the mock send `handledBy.name: null` for internal users on an unassigned case.

### A5. Old · pending isn't ordered by age (coordinator, mock)

- Spec §16: `old_pending` returns open cases older than the threshold, oldest first. Home says "Open the longest".
- Actual: DRLR261022106911 (raised 22 Oct) is listed before COC261020106800 (raised 20 Oct), because the mock sorts by `updatedAt` and reverses.
- File: `mobile/src/mock/server.ts` lines 349–352.
- Proposal: for `assignment === 'old_pending'`, sort by `createdAt` ascending and ignore `q.sort` (drop the `reverse()`).

## Observations

- O1. Admin has an Updates tab (`mobile/src/navigation/RootNavigator.tsx` line 43 hides it only for management). AdminHome.dc.html shows Home, Assign, Cases, Account. It's harmless, since admin gets no notifications in the mock, but it's not in the design. Coordinator to decide; hiding it for admin too would match the board.
- O2. On this emulator, `10.0.2.2:8081` was intermittently unreachable. The mock's offline check (`src/mock/index.ts` `deviceOnline`, which probes the bundle's origin) then failed calls with "You appear to be offline" at sign-in and on case detail. Workaround used: debug host set to `localhost:8081` in the app's dev settings (adb reverse is in place). With that set, airplane mode no longer simulates offline (adb tunnels Metro), so offline was simulated by removing the adb reverse for a few seconds. Not an app defect.
- O3. Assigned-case cards show the dealer-facing latest update ("Your case is with PQMP Support.") to admin. That's acceptable, but internal users might prefer the internal latest event.

## Gaps

- Paging and infinite scroll in the workbench weren't exercised: the mock has 6 open cases and the page size is 20.
- Error responses from `POST /cases/{id}/assignment` (`CASE_CLOSED`, `ALREADY_ASSIGNED`, 403) weren't triggered on the device; the mock has no trigger for them. The sheet's inline handling is covered only by code review.
- The overdue and closure-eligible filters (SRS 13.12) are out of scope until approved.
- iOS not tested. Maestro flows not run (Maestro not installed).
